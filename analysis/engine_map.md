# ROM 還原記錄

## 來源和邊界

- ROM：`中國象棋 [TXC].nes`，40976 字節。
- SHA-256：`f2a8aadfba05ed8566d3ec54285aca9ee2bb9408658e2a67f0cdea3aa1969f9b`。
- iNES 頭部：`4e45531a020100000000000000000000`。PRG 32768 字節，CHR 8192 字節。
- 棋力計算入口：CPU `$8597`，輸入 A 爲檔位、`$C7` 爲行棋方、零頁爲棋盤和棋子位置；返回 `$C0/$C1` 爲着法。
- 控制流提取覆蓋 5762 條指令、11996 字節可達代碼，包括走法分派表指向的子程序。代碼與數據穿插，函數之間存在無用字節，不能僅憑線性反彙編劃定函數。

## 已保留的原程序特殊行爲

1. 評分內部以 `$8000` 爲零點；黑將被喫的分值包含 `$A23C` 中未先置進位的 SBC 效果，不能直接套用對稱將殺分。
2. 根走法上限爲 80。可以直接喫將帥時返回該着法，並保留根生成器的原始順序。
3. 迭代加深窗口偏移爲 50，喫子延伸與將軍分支有各自終止條件。保留雙殺手排序、回喫排序及重複着法篩選。
4. `$B1BC/$B544` 的重複着法測試返回後，X 仍爲棋盤格編號，跳過了重載當前深度的指令。後續主變化／窗口操作可能使用這個編號。C 中以 `ordering_index` 明確保留；修正成常規算法會改變深層節點數。
5. 選擇性回喫分支可能臨時移動另一方棋子。原評分按當前搜索方更新，因此 C 也按行棋方選擇評分正負。
6. 某些舊主變化可以暫時引用空起點。原程序將 piece 0 的位置表指向全 `$FF` 的 `$FBC8`，其位置分差爲零。C 顯式處理零分差，避免數組越界；不暴露原 RAM 中無用的 piece 0 位置槽變化。
7. `$85A8` 會讀取遊戲 RAM 的 `$0436/$0454`，當 `ram[0436] ^ ram[0454] ^ rom[D015] ^ rom[D017] == 0` 時將根着法數量改爲 `(count & 1) + 1`。提供 `txc_search_compat(..., limit_root_moves)` 保留這條分支；默認獨立引擎不觸發它。上層遊戲何時改變這些 RAM 值不在此核心接口中推測。

## 驗證範圍與差異

- 對照基準直接運行用戶 ROM 的 `$8049`、`$8701`、`$8886`、`$8597`，不是另外寫一個現代象棋引擎作基準。
- 走法測試逐項比較返回結果和整個有序着法列表；評分比較原始數值；撤銷和搜索檢查輸入狀態恢復。
- 搜索測試同時比較最優着法、評分和節點數。ROM 計數器僅 16 位，C 提供 64 位計數，對照時比較低 16 位。
- 初始局面用 `$E1FD` 的 32 個原始身份校驗。最高檔紅方結果爲 `h2e2`、評分 0、18644 個節點。
- 測試覆蓋隨機合法對局生成的局面，以及將軍、炮架、馬殘局、直接喫將、缺將、選擇性回喫、空起點主變化和外部根着法限制分支。具體數量以 JSON 報告爲準。
- 這不是對所有可能 RAM 狀態和全部合法象棋局面的窮盡證明；任意損壞內存、非法輸入、遊戲 UI 狀態和執行時序不承諾一致。
- 對外 API 在沒有着法時返回 `from=255`，在唯一着法時給出靜態評分；原 ROM 此時部分評分 RAM 可能是舊值。該輸出約定不改變原引擎的着法選擇。
- 獨立引擎沒有另加現代長將／長捉裁判規則、開局庫或新的局面評分。
