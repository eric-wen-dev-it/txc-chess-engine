# ROM 还原记录

## 来源和边界

- ROM：`中国象棋 [TXC].nes`，40976 字节。
- SHA-256：`f2a8aadfba05ed8566d3ec54285aca9ee2bb9408658e2a67f0cdea3aa1969f9b`。
- iNES 头部：`4e45531a020100000000000000000000`。PRG 32768 字节，CHR 8192 字节。
- 棋力计算入口：CPU `$8597`，输入 A 为档位、`$C7` 为行棋方、零页为棋盘和棋子位置；返回 `$C0/$C1` 为着法。
- 控制流提取覆盖 5762 条指令、11996 字节可达代码，包括走法分派表指向的子程序。代码与数据穿插，函数之间存在无用字节，不能仅凭线性反汇编划定函数。

## 已保留的原程序特殊行为

1. 评分内部以 `$8000` 为零点；黑将被吃的分值包含 `$A23C` 中未先置进位的 SBC 效果，不能直接套用对称将杀分。
2. 根走法上限为 80。可以直接吃将帅时返回该着法，并保留根生成器的原始顺序。
3. 迭代加深窗口偏移为 50，吃子延伸与将军分支有各自终止条件。保留双杀手排序、回吃排序及重复着法筛选。
4. `$B1BC/$B544` 的重复着法测试返回后，X 仍为棋盘格编号，跳过了重载当前深度的指令。后续主变化／窗口操作可能使用这个编号。C 中以 `ordering_index` 明确保留；修正成常规算法会改变深层节点数。
5. 选择性回吃分支可能临时移动另一方棋子。原评分按当前搜索方更新，因此 C 也按行棋方选择评分正负。
6. 某些旧主变化可以暂时引用空起点。原程序将 piece 0 的位置表指向全 `$FF` 的 `$FBC8`，其位置分差为零。C 显式处理零分差，避免数组越界；不暴露原 RAM 中无用的 piece 0 位置槽变化。
7. `$85A8` 会读取游戏 RAM 的 `$0436/$0454`，当 `ram[0436] ^ ram[0454] ^ rom[D015] ^ rom[D017] == 0` 时将根着法数量改为 `(count & 1) + 1`。提供 `txc_search_compat(..., limit_root_moves)` 保留这条分支；默认独立引擎不触发它。上层游戏何时改变这些 RAM 值不在此核心接口中推测。

## 验证范围与差异

- 对照基准直接运行用户 ROM 的 `$8049`、`$8701`、`$8886`、`$8597`，不是另外写一个现代象棋引擎作基准。
- 走法测试逐项比较返回结果和整个有序着法列表；评分比较原始数值；撤销和搜索检查输入状态恢复。
- 搜索测试同时比较最优着法、评分和节点数。ROM 计数器仅 16 位，C 提供 64 位计数，对照时比较低 16 位。
- 初始局面用 `$E1FD` 的 32 个原始身份校验。最高档红方结果为 `h2e2`、评分 0、18644 个节点。
- 测试覆盖随机合法对局生成的局面，以及将军、炮架、马残局、直接吃将、缺将、选择性回吃、空起点主变化和外部根着法限制分支。具体数量以 JSON 报告为准。
- 这不是对所有可能 RAM 状态和全部合法象棋局面的穷尽证明；任意损坏内存、非法输入、游戏 UI 状态和执行时序不承诺一致。
- 对外 API 在没有着法时返回 `from=255`，在唯一着法时给出静态评分；原 ROM 此时部分评分 RAM 可能是旧值。该输出约定不改变原引擎的着法选择。
- 独立引擎没有另加现代长将／长捉裁判规则、开局库或新的局面评分。
